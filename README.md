# Quant Portfolio — Cross-Sectional Equity Alpha

**Vedant Konde · 2027 quant recruiting cycle.** I build systematic alpha and the
research infrastructure that makes an alpha claim defensible. This repository is the
first and central deliverable: a hedge-fund-grade pipeline that turns a point-in-time
equity universe into a market- and sector-neutral long-short book, and validates it with
the discipline that separates a result from a coincidence.

**The question:** can a cross-sectional model rank 120 names by their 21-day forward
return *out of sample*, net of realistic costs, without any single leaky feature, any
survivorship-biased universe, or any in-sample number smuggled into the headline?
**The answer (one command below):** OOS rank IC **0.149** (IC IR 0.95) across the last
two OOS years, OOS net Sharpe **2.67** gross-of-nothing — and the deliberately leaky
control feature is caught by the guardrail at Spearman IC **1.000**, so the validator
that is supposed to catch a rookie mistake actually does.

Everything is deterministic: one seed, one config, one command reproduces every number
in this README and in the research note, from the raw generated data.

## Results

Primary strategy: LightGBM on 15 decision-time features (technical, fundamental,
PEAD), anchored walk-forward with purged training blocks, market/sector-neutral
long-short book, 21-day rebalance, 5 bp round-trip costs. Default dataset is a
seeded 120-ticker synthetic market (2008–2025) with real PIT structure: staggered
listings/delistings, splits, dividends, earnings surprises. The real-data loaders
(`src/alpha/data/loaders.py`) plug into the identical contracts.

| OOS rank IC (mean, per-date) | **0.149** | 0.200 | −0.180 |
| OOS IC IR | 0.95 | 1.19 | −1.06 |
| OOS net Sharpe (annualized) | **2.67** (gross 2.74) | — | — |
| Turnover per 21-day rebalance | 1.00 single-side | — | — |
| Deflated Sharpe (24 trials, DSS) | 0.748 → **not significant at 5%** | — | — |
| OOS window | 2024-01-26 → 2025-12-02 (483 rebalance dates) | same | same |

**Capacity:** at $100M AUM, one 21-day rebalance trades ~$0.4M per name per day,
≈ **0.03% of median per-name ADV** ($1.26e9 in this universe) — square-root impact
is negligible to $1B AUM at this turnover; the break-even curve lives in
`src/alpha/costs/model.py::capacity_curve`. **Leak guardrail:** `leaky_ic = 1.000`
(flagged, excluded from every result above). **Pre-registered kill criteria**
(`configs/preregistration.yaml`): OOS rank IC ≥ 0.02, IC IR ≥ 0.30, net Sharpe ≥
0.50 — **all met**. What did *not* survive: the multiple-testing correction. DSS
0.748 means the raw Sharpe is optimistic; the note reports it as such, which is the
whole point of running it.

## How to run

```
cd quant-portfolio
make report        # or: bash scripts/make_report.sh
```

One command, end to end: generate the seeded market → write `data/*.parquet` +
manifest → point-in-time universe → features + forward labels → three-model
purged walk-forward → neutral long-short book → backtest with costs → deflated
Sharpe → leak guardrail → experiment JSON + research note + figures.
`make test` runs the full 46-test suite (PIT audit, leak guardrail, 20bp
equal-weight pin, cost-model identity, label purity). Python ≥ 3.11 with
`numpy, pandas, scipy, scikit-learn, lightgbm, pyarrow, matplotlib, pyyaml`
(`pyproject.toml`); on this machine the interpreter is `py -3`.

## How to evaluate this work

Probe these questions; each one has a specific place to look.

1. **Is any number in-sample?** The headline is OOS-only; check
   `src/alpha/validation/walkforward.py` — the anchored walk-forward never
   shuffles time, and the note renderer (`src/alpha/reporting/note.py`)
   refuses to lead with anything but the `oos` block.
2. **Is a leak actually caught, not just asserted?** Run
   `py -3 -m pytest tests/test_guardrail.py -q`. The leaky table
   (`leaky` in `data/*.parquet`) is the 21-day forward return joined back as
   a feature; the guardrail must flag it at Spearman IC ≈ 1.0. It does.
3. **Is the universe survivorship-aware?** `src/alpha/data/universe.py`
   keeps delistings in `eligible_universe`; the synthetic generator
   (`src/alpha/data/synthetic.py`) delists ~45% of names mid-sample. The
   equal-weight pin (`tests/test_universe.py`) must land within 20bp of an
   independent reference implementation — it is an identity check, not a
   performance claim.
4. **Are costs honest or decorative?** `src/alpha/costs/model.py` charges
   commission + half-spread + square-root impact + borrow per unit turnover;
   the note prints both the net number and the 3× slippage-shock variant.
   `tests/test_costs.py` pins each term.
5. **What kills this result?** The pre-registration
   (`configs/preregistration.yaml`) was written before tuning. The one
   criterion that *did* trip on the default seed — the deflated Sharpe — is
   reported in the note as not significant, not hidden. Read
   [docs/limitations.md](docs/limitations.md) for the full list of things
   I will not claim.
